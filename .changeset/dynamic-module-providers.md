Read the metadata a `DynamicModule` registers, not only the `@Module()` decorator, so `correctness/injectable-must-be-provided` and `performance/no-unused-providers` stop reporting a class listed only in the `providers` or `exports` of an object returned by `forRoot()`, `register()`, a static method of any name, a standalone function, a `ConfigurableModuleBuilder` `setExtras` callback, or an inline `{ module, providers }` literal in another module's `imports`, and `performance/no-unused-module-exports` stops reporting an export whose only consumer is registered that way. A literal counts by the test Nest applies at runtime: a `module` key, the decorator argument (a same-file constant too), the returned value of a function typed `DynamicModule`, or the `setExtras` transform; the array itself may be a local variable, a `push`, a spread, a `concat`, a ternary, a static helper or an imported function. A `forRootAsync({ useClass })` option registers that class on the module it is passed to. Because the graph now sees these providers, `correctness/no-missing-injectable` checks them, an `APP_GUARD` bound inside a `forRoot()` quiets `security/require-guards-on-endpoints`, a `{ module: X }` literal in `imports` adds an edge to `X` for `architecture/no-circular-module-deps` and `performance/no-orphan-modules`, and the report attributes each provider to the module that registers it; `imports` inside the literal still add no edge. A `providers` key in anything else, such as a testing module in a helper file, a plain registry object, or an OAuth or webpack config, registers nothing.
