Read the metadata a `DynamicModule` registers, not only the `@Module()` decorator, so `correctness/injectable-must-be-provided`, `performance/no-unused-providers` and `performance/no-unused-module-exports` stop reporting a class whose only registration is the `providers` or `exports` of an object returned by `forRoot()`, `register()`, a static method of any name, a standalone function, a `ConfigurableModuleBuilder` `setExtras` callback, an inline `{ module, providers }` literal in `imports`, or a `forRootAsync({ useClass })` option. A literal counts by the test Nest applies at runtime (a `module` key, the decorator argument, the returned value of a function typed `DynamicModule`, or the `setExtras` transform), and the array may be a local variable, a `push`, a spread, a `concat`, a ternary, a static helper or an imported function. The same providers now reach `correctness/no-missing-injectable`, an `APP_GUARD` bound inside a `forRoot()` quiets `security/require-guards-on-endpoints`, a `{ module: X }` literal in `imports` adds an edge to `X` for `architecture/no-circular-module-deps` and `performance/no-orphan-modules`, a `global: true` in the literal makes every module a consumer for `performance/no-unused-module-exports`, and the report attributes each provider to the module that registers it; `imports` inside the literal still add no edge, and a `providers` key on a testing module, a registry object or a config object registers nothing.
