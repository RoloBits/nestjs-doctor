# Output

**Source:** `src/cli/formatters/console-reporter.ts`, `src/cli/formatters/json-reporter.ts`

## What

Renders the final scan results in the requested format.

## Why

Different use cases need different formats. Humans want the visual console report. CI pipelines want `--score` or `--json`. Tooling integrations want structured JSON they can parse.

## Input

```typescript
interface DiagnoseResult {
  score: Score
  diagnostics: Diagnostic[]
  project: ProjectInfo
  summary: DiagnoseSummary
  ruleErrors: RuleErrorInfo[]
  schema?: SerializedSchemaGraph
  elapsedMs: number
}

interface DiagnoseSummary {
  total: number
  errors: number
  warnings: number
  info: number
  byCategory: Record<Category, number>
}
```

## Output Formats

### Console Report (default)

The visual report includes:

- ASCII art NestJS bird (happy, neutral, or sad based on score)
- Score display: `82 / 100  ★★★★☆  Good`
- Score bar visualization
- Summary: error/warning/info counts, file count, elapsed time
- Project info: name, NestJS version, ORM, module count
- Diagnostics grouped by rule, sorted by severity
- With `--verbose`: file paths and line numbers per diagnostic

Color coding:
- Green: score >= 75
- Yellow: score >= 50
- Red: score &lt; 50

### JSON (`--json`)

Full `DiagnoseResult` as pretty-printed JSON to stdout:

```bash
npx nestjs-doctor . --json
```

Useful for piping into other tools:

```bash
npx nestjs-doctor . --json | jq '.diagnostics[] | select(.severity == "error")'
```

### Score Only (`--score`)

Just the numeric score:

```bash
npx nestjs-doctor . --score
# Output: 82
```

Useful for CI scripts that need to capture the score:

```bash
SCORE=$(npx nestjs-doctor . --score)
```

### Monorepo Report

In monorepo mode, the console report shows:

1. Combined score and diagnostics (same as single project)
2. Per-project breakdown table:

```
  Project     Score    Files   Errors  Warnings  Info
  api         85/100   42      1       3         0
  admin       78/100   31      2       2         1
  shared      95/100   18      0       1         0
```

### HTML Report (`--report`)

Generates a self-contained HTML file with an interactive report:

```bash
npx nestjs-doctor . --report
```

The report includes six tabs:

- **Summary** — health score overview with category breakdown
- **Diagnosis** — source-level findings with code viewer and fix examples
- **Modules Graph** — clustered module diagram with a searchable project sidebar, a per-module detail panel (used by, blast radius, providers, imports, exports, wiring), direction-colored animated edges on selection, cycle focus, toggles for `@Global()` reach and external modules, and a problems drawer listing module-wiring findings (rules tagged `module-graph`, custom rules included). With `--timings`, each node also shows its slowest class's bootstrap construction time and the detail panel lists every class slowest-first
- **Endpoints** — traced HTTP routes per controller with their dependency chains; controllers and handlers behind project wrapper decorators (a custom decorator composing `@Controller()` or `@Get()`) are resolved and traced
- **Schema ER Diagram** — entity-relationship visualization of database models
- **Lab** — custom rule playground to write and test your own rules

Output: `nestjs-doctor-report.html` in the project root, auto-opened in the default browser.

### Bootstrap timings (`--timings`)

Overlays real per-class construction times from a captured boot onto the modules graph. NestJS records `initTime` for every provider and controller during dependency injection; `{ snapshot: true }` assembles them into a `SerializedGraph` you can dump locally (requires `@nestjs/core` >= 9.3). Add to `main.ts` (dev only):

```ts
import { NestFactory, SerializedGraph } from "@nestjs/core";
import { writeFileSync } from "node:fs";

const app = await NestFactory.create(AppModule, { snapshot: true });
writeFileSync("nestjs-doctor-timings.json", app.get(SerializedGraph).toString());
```

Boot the app once, then:

```bash
npx nestjs-doctor . --report --timings nestjs-doctor-timings.json
```

Each time includes waiting on that class's own dependencies, so a shared slow dependency counts again in every class that awaits it — module nodes therefore show the slowest single class, never a sum. Selecting a module draws its classes and their times as a card directly on the canvas, and the header gains a `boot ≈ <ms>` badge for the slowest chain in the whole boot. Clicking a class in the detail panel opens a Gantt-style boot trace in a bottom drawer: the injection cascade as nested bars, where the bar is the class's total time and an amber segment marks the part not explained by its slowest dependency (≈ its own work). Read down the cascade until the number drops — the class where it drops owns the time. Timings are display-only: they never affect the score, diagnostics, or exit codes. An unreadable or unrecognized dump degrades to a stderr warning and the report renders without timings. In a monorepo, a timing attaches only when its module class name is unique across projects.

## Exit Codes

| Code | Meaning |
|------|---------|
| `0` | Score is at or above threshold (or no threshold set) |
| `1` | Score is below `--min-score` threshold, or errors were found |
| `2` | Invalid input (bad path, invalid flags) |

All output formats respect exit codes. The `--min-score` check happens after output, so you always see the report even when the exit code is 1.
