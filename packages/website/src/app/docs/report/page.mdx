# The report

Write the interactive HTML report:

```bash
npx nestjs-doctor@latest . --report
```

Writes `nestjs-doctor-report.html` to the project root and opens it. One file,
no server, no build step. Commit it or attach it to a pull request.

It loads three things from a CDN when opened: the graph layout library, the
code viewer, and the logo. Offline, the module graph falls back to a plain grid
and the code viewers do not load. Everything else works.

![Module graph](/module-graph.png)

## What is in it

| Tab | Shows |
|---|---|
| Summary | The score, the category breakdown, and the counts behind them |
| Diagnosis | Every finding with a code viewer and a fix example |
| Modules graph | Your real module graph, clustered, with cycles in red |
| Endpoints | Traced HTTP routes per controller and the dependencies each one pulls |
| Schema | The ER diagram extracted from your ORM |
| Lab | A playground for writing a custom rule against your own code |

Pick a module in the graph. The detail panel lists what it imports, exports,
provides, and what breaks if you change it.

## Boot trace

The graph can overlay how long each class took to construct during a real boot.
NestJS records the timings itself, and `--timings` reads the dump:

```bash
npx nestjs-doctor@latest . --report --timings nestjs-doctor-timings.json
```

Producing the dump takes one change to `main.ts`, documented in
[Output](/docs/pipeline/output#bootstrap-timings---timings). Boot the app once, then scan.

Each class's time includes waiting on its own dependencies, so a shared slow
dependency counts again in every class that awaits it. Module nodes show the
slowest single class, never a sum. Read down the cascade until the number drops:
the class where it drops owns the time.

Timings never affect the score, the diagnostics, or the exit code.
